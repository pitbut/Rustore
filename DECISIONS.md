# Решения, принятые по умолчанию

## Проект
- Один Gradle-модуль `app`, слои разделены пакетами: `core`, `data` (mock/remote/local/repo), `domain`, `feature/*` (auth, home, lobby, game, social, questions, profile, settings), `design`, `voice`, `sound`, `push`, `navigation`. Так быстрее собирать; при росте команды пакеты переносятся в модули без изменения кода.
- Kotlin 2.1.21, AGP 8.11, compileSdk/targetSdk 36, minSdk 26, JDK 17-байткод.
- Название «Клуб знатоков» хранится в `strings.xml` (`app_name`) и `BuildConfig.APP_TITLE`; package name — `APP_ID` в `gradle.properties`.
- `USE_MOCK = true` и в debug, и пока в release (сервера ещё нет). В debug есть переключатель в «Настройки → Отладка» (перезапускает приложение).

## Игровая логика
- Клиент ничего не решает: фазы, таймеры, результат волчка, проверка ответа, счёт — только из событий сервера. Состояние комнаты собирает чистый редьюсер `GameReducer` (дубликаты по `seq` игнорируются, при разрыве последовательности клиент шлёт `game:ack` и получает `room:state`).
- Все таймеры рисуются от `endsAt` (серверное время) с поправкой offset из `GET /time` (`ServerClock`), offset пересчитывается при каждом входе.
- Волчок: `SpinMath.angleAt(spin, serverNow − startedAt)`; кривая — короткий разгон × `cubic-bezier(0.18, 0.62, 0.16, 1)` + затухающая качка, равная нулю на финише. При лаге анимация догоняет по времени; при «убрать анимации» сразу показывается финал. Тест на 1000 seed подтверждает точное совпадение сектора.
- Ранний ответ: в копилку уходит остаток, округлённый вниз до 5 с. Доп. минута тратит сначала лимит игры, затем копилку (до 60 с).
- Голосования (доп. минута, исключение) идут поверх текущей фазы и не останавливают таймер обсуждения. Голосование за доп. минуту, не завершённое к концу обсуждения, закрывается.
- Апелляция доступна при вердикте `incorrect` с непустым ответом (для `disputed` очко уже засчитано). Мок «более сильной модели» расширяет допуск опечаток и сравнивает основы слов.
- В суперблице игрока выбирает случайность (или капитан, если включено и капитан — вы); остальным выставляется `micMutedByHost`.
- Если все сектора сыграны раньше, чем кто-то набрал 6 очков (актуально для стола из 7 секторов), стол открывается заново.

## Голос и звук
- LiveKit: шумо- и эхоподавление, автоусиление; индикаторы «говорит» из `ActiveSpeakersChanged`; LiveKit сам переподключается при смене сети. Режимы «открытый микрофон» и «нажми и говори».
- Foreground-service типа `microphone` запускается после выдачи `RECORD_AUDIO` и останавливается при выходе из комнаты.
- В мок-режиме голос эмулируется: «говорит» тот, кто только что написал в чат команды.
- TTS ведущего: реплики, пришедшие во время обсуждения, откладываются до его конца. Реплики ботов («Версия: …») звучат сразу разными голосами (питч и темп).
- Все звуки (тик, гонг, раскрутка, сигнал «10 секунд», верно/неверно) и фоновая музыка синтезируются в коде (`SynthAudio`) и кэшируются в WAV. Сторонних аудиофайлов нет.

## Пуши
- Интерфейс `PushProvider` + заглушка `NoopPushProvider`. FCM не подключён: для него нужен `google-services.json` от вашего Firebase-проекта, а без файла плагин Google Services ломает сборку. RuStore Push SDK подключается реализацией того же интерфейса и вызовом `POST /devices`.

## Безопасность
- Токены хранятся в EncryptedSharedPreferences (Android Keystore); `allowBackup=false`.
- Только HTTPS (Network Security Config). Пиннинг сертификата не включён, пока у сервера нет финального сертификата (место отмечено в RELEASE.md).
- OkHttp `Authenticator` обновляет access-токен по 401 через `/auth/refresh`; заголовок Authorization вырезается из логов; в release логов уровня debug нет (R8 `assumenosideeffects`).
- Клиентский фильтр мата (`Profanity`) маскирует текст перед отправкой; сервер остаётся основным фильтром.

## Локализация
- `values/` — русский (язык по умолчанию), `values-uz/` — узбекский (латиница). Выбор языка внутри приложения: `LocaleManager` на API 33+, обёртка контекста ниже.
- Тексты вопросов и реплики ведущего — это контент сервера, в ресурсы они не выносятся.

## Мок
- `FakeGameServer` целиком эмулирует REST и Socket.IO: часы мок-сервера сдвинуты на +1,25 с, чтобы проверять логику offset. Боты обсуждают в чате, голосуют, отвечают с вероятностью, зависящей от уровня и сложности. Капитан-бот с вероятностью 70 % берёт вашу последнюю версию из чата.
- Любой e-mail и пароль от 8 символов подходят для входа; код подтверждения — любые 6 цифр.
- В открытых играх (зритель) играют только боты, а капитан-бот иногда зовёт зал, чтобы можно было подсказать.

## Не сделано или ограничено (см. README)
- Не запускалось на эмуляторе или устройстве: в облачной среде сборки нет аппаратной виртуализации. Логика и UI-компоненты проверены JVM-тестами (Robolectric).
- Инструментальные UI-тесты (androidTest) не написаны; UI-тесты выполняются в Robolectric.
- Загрузка картинки к вопросу: в мок-режиме сохраняется локальный URI; для сервера нужен эндпоинт загрузки файлов (в контракте его нет).

## v1.0.2
- **Выбор отвечающего.** Новая фаза `CHOOSE_ANSWERER` (10 с): капитан выбирает любого участника команды (`game:choose_answerer {playerId}`); не выбрал — отвечает сам. Сервер присылает `game:answerer {playerId}` и `RoomState.answererId`. Фаза `ANSWER` длится 30 с, отвечает только `answererId`. В суперблице выбор пропускается (отвечает выбранный для суперблица игрок), в блице выбор делается перед каждым вопросом. Капитану при начале выбора и выбранному игроку при начале ответа — звуковой сигнал и вибрация.
- **Вход через Google** — Credential Manager → ID-токен → `POST /auth/google {idToken}`. Кнопка показывается, только если в `gradle.properties` задан `GOOGLE_WEB_CLIENT_ID`. На телефонах без сервисов Google (Huawei) — сообщение «войдите по e-mail».
- **Вход сохраняется на телефоне.** Продление сессии строго по одному запросу (`TokenRefresher`): сервер отзывает сессию при повторном использовании refresh-токена, а параллельные 401 раньше могли вызвать двойное продление. Сессия сбрасывается только при явном отказе сервера (400/401/403), а не при отсутствии сети; при запуске без интернета пользователь остаётся в аккаунте. Socket.IO продлевает токен перед переподключением и по `connect_error: unauthorized`.
- Серверная часть этих изменений описана в `docs/prompt-3-server-update.md`.
